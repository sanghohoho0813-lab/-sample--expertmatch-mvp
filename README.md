# (sample) ExpertMatch — 전문가 상담·매칭 플랫폼 MVP

[![CI](https://github.com/sanghohoho0813-lab/-sample--expertmatch-mvp/actions/workflows/ci.yml/badge.svg)](https://github.com/sanghohoho0813-lab/-sample--expertmatch-mvp/actions/workflows/ci.yml)

전문가 목록을 보여 주는 데서 끝나지 않고, **사용자의 고민을 이해해 맞는 전문가를 고르도록 돕는**
상담 플랫폼 데모입니다. **고민 정리(맞춤 찾기) → 탐색·비교 → 상세 확인 → 상담 예약 → 상담 준비 → 상담방 → 후기·재상담**까지
실제로 체험할 수 있는 반응형 웹앱입니다.

> 포트폴리오 / 정부지원사업 시연용 데모입니다. 실제 결제·상담·채팅은 진행되지 않습니다.

## 실행

```bash
npm install
npm run dev        # http://localhost:3000
npm run build      # 프로덕션 빌드
npm run check      # typecheck + lint + 단위 테스트
npm run test:e2e   # 빌드 후 실행 — Playwright (데스크톱 + 모바일)
```

Vercel에 그대로 배포할 수 있습니다. 선택 환경변수 `NEXT_PUBLIC_SITE_URL` 은
OG 이미지·사이트맵의 절대 주소에 쓰이며, 없으면 Vercel 배포 주소를 사용합니다.

### 설계 메모

- **예약 가능 시간은 한 곳에서** (`lib/availability.ts`) — 카드·상세·비교·달력이 같은 함수를 써서
  숫자가 어긋나지 않습니다. 겹침 판정은 순수 함수(`lib/bookingRules.ts`)로 분리해 테스트합니다.
- **저장소는 신뢰하지 않는다** (`lib/store/persist.ts`) — localStorage 값은 항목 단위로 검증하고,
  손상·구버전 데이터는 고치거나 버립니다. 다른 탭의 변경은 `storage` 이벤트로 즉시 반영합니다.
- **시간에 의존하는 값은 마운트 후 계산** (`useNow`) — 서버/클라이언트 렌더 불일치를 막습니다.
- **예약 단계는 주소에 기록** (`?step=`) — 브라우저 뒤로가기가 이전 단계로 동작합니다.
- **추천은 판정만, 점수는 숨긴다** (`lib/needs.ts`) — 조건마다 실제 데이터와 맞음/아님을 판정하고,
  정렬용 점수는 화면에 노출하지 않습니다. '매칭률 92%' 같은 근거 없는 숫자는 쓰지 않습니다.
- **비교 문장도 데이터에서** (`lib/compareInsights.ts`) — "이런 경우에는 A"는 비교 중인 전문가들의
  상담료·경력·예약 가능 시간·방식·대상을 서로 견줘서 만들고, 값이 같으면 우열을 만들지 않습니다.
- **변경·취소·상담방 규칙은 한 곳에서** (`lib/bookingRules.ts`) — 시작 30분 전까지 변경·취소,
  10분 전부터 상담방 입장. 예약 상세·마이페이지·상담방이 같은 함수를 씁니다.

## 핵심 사용자 Journey

```
홈 ─┬─ 맞춤 찾기(질문 5개) → 추천 3명 + 조건별 근거 → 한 번에 비교 ─┐
    └─ 검색/카테고리 → 전문가 목록 → 필터·정렬 → 비교(최대 3명) ──┤
                                                                    ↓
   전문가 상세 → 상담 상품 → 상담 방식 → 날짜 → 시간 → 상담 내용 → 예약 확인
   → 예약 완료 → 상담 전 준비(체크리스트) · 일정 변경/취소 → 상담방(10분 전 입장)
   → 상담 완료 → 후기 · 같은 전문가 재상담
```

전 과정이 실제로 동작합니다.

## 데이터

- **전문가 12명** — 분야, 경력, 평점, 상담 건수, 상담료, 상담 방식, 예약 가능 여부가 모두 다릅니다.
  각자 주요 상담 대상(개인 / 예비·초기 창업자 / 사업자·기업), 이런 분께 맞아요 3가지, 상담 후 얻는 것 3가지를 가집니다.
- **상담 상품** — 상품마다 이런 경우에 고르세요 · 상담이 끝나면 받는 것 · 준비하면 좋은 것이 있습니다.
- **리뷰 30개** — 실제 상담 후기 형태의 한국어 문장 (Lorem ipsum 없음).
- **상담 슬롯** — `expertId + 날짜` 해시 기반으로 생성되어 새로고침해도 동일합니다.
  일요일 휴무, 토요일 축소 운영, 일부 날짜 마감이 반영되며,
  오늘 날짜는 이미 지난 시간과 1시간 이내 임박한 시간을 제외합니다.
- **예약 가능 시간은 한 곳에서 계산** — `src/lib/availability.ts` 의
  `openSlots / slotStates / earliestSlot / openSlotCount` 가 저장된 예약과 겹치는
  시간을 빼고 계산하므로, 카드 · 상세 · 비교 · 예약 화면의 "가장 빠른 예약"과
  남은 자리 수가 항상 일치합니다. 예약하면 그 시간은 즉시 `예약됨`으로 바뀌고,
  취소하면 다시 열립니다. 같은 시간대의 다른 전문가 예약은 `내 다른 예약`으로 막습니다.

### 상태 저장

찜 / 비교 / 예약 내역 / 최근 본 전문가 / 내가 쓴 후기는 `localStorage` 키 `expertmatch:v1` 에 저장됩니다.
예약은 `upcoming → done | cancelled` 상태를 가지며, 취소해도 기록은 남습니다
(종료 시각이 지난 예정 상담은 화면에서 완료로 표시). `addBooking` 은 겹치는 예약을 거부합니다.
localStorage 는 마운트 이후에만 읽어 Hydration 불일치가 발생하지 않도록 처리했습니다.

### Supabase

`supabase/schema.sql` 에 `users / experts / expert_categories / expert_skills /
consultation_products / availability / bookings / reviews / favorites` 테이블과
RLS 정책을 정의해 두었습니다. Mock 데이터 구조와 1:1로 대응하므로 데이터 소스만
교체하면 됩니다.

## 샘플 브릿지 CTA

샘플을 다 본 사용자를 상담·다른 샘플·홈페이지로 연결하는 공통 CTA입니다.
푸터 바로 위에 **모든 페이지 공통**으로 노출됩니다.

| 파일 | 역할 |
| --- | --- |
| `src/components/brand/SampleBridgeCTA.tsx` | CTA 본체 (재사용 가능한 프레젠테이션 컴포넌트) |
| `src/components/brand/SampleBridgeSlot.tsx` | 레이아웃에 한 번만 두고 노출 페이지를 판단하는 슬롯 |
| `src/lib/mirae.ts` | **링크·문구 상수 — 수정은 이 파일에서** |

구성은 `배지 → 제작사 한 줄 → 헤드라인 → 설명 → 메인 CTA → 서브 액션` 순입니다.
메인 CTA 라벨은 모든 샘플에서 **"우리 회사도 만들어보기"** 로 통일합니다.

### 링크 수정

`src/lib/mirae.ts` 의 `MIRAE_LINKS` 만 바꾸면 전 페이지에 반영됩니다.
`https://` 로 시작하면 자동으로 새 탭으로 열립니다.

```ts
export const MIRAE_LINKS = {
  consult: "https://miraeailab.com/business-diagnosis", // 우리 회사도 만들어보기
  samples: "https://miraeailab.com/business-services",  // 다른 샘플 보기
  home: "https://miraeailab.com/",                      // 미래AI랩 홈페이지
};
```

### 문구 수정

같은 파일의 `MIRAE_CTA_COPY` 에서 배지·헤드라인·설명·버튼 라벨을 관리합니다.
특정 페이지에서만 다르게 쓰려면 props 로 덮어씁니다.

```tsx
<SampleBridgeCTA
  consultHref="https://..."
  headline={"이 샘플이 마음에 드셨다면,\n대표님 회사도 이렇게 설계해볼 수 있습니다."}
  description="..."
/>
```

### 노출 규칙

`SampleBridgeSlot` 의 `HIDDEN_PATHS` 로 제어합니다. 기본값은 예약 진행 중
(`/booking/[id]`)만 제외 — 하단이 단계 CTA로 고정되어 있어 경쟁하지 않도록 합니다.
예약 완료 화면(`/booking/complete`)에는 노출됩니다.

### 애니메이션

메인 CTA에 6.5초 주기의 아주 약한 light sweep, 배지 뒤에 4.5초 주기의 은은한 glow만
적용했습니다 (`tailwind.config.ts` 의 `sheen` / `badge-glow`). hover 시 살짝 떠오르며,
`prefers-reduced-motion: reduce` 환경에서는 두 효과 모두 렌더링되지 않습니다.

## UX 상세

### V2 — 목록을 보여 주는 서비스에서, 고르도록 돕는 서비스로

- **맞춤 찾기** — 검색은 그대로 두고, 원하는 사람만 질문 5개(분야 · 대상 · 방식 · 예산 · 시기)에 답합니다.
  결과는 `창업 주력 · 화상 가능 · 예산 안 · 이번 주 예약 가능`처럼 **조건별로 맞음/아님**을 보여 주며,
  모든 조건을 만족하는 사람이 적으면 "'8만 원 이하' 조건을 빼면 2명이 더 맞아요"처럼 어떤 조건이 막고 있는지 알려 줍니다.
- **이어지는 맥락** — 답한 방식은 예약의 방식 단계에, 남긴 고민 메모는 상담 내용에 미리 채워지고(출처 표시 · 비우기 가능),
  검색 목록과 비교 화면도 같은 조건으로 대조합니다.
- **비교 = 결정 화면** — 표 앞에 `한눈에 보는 차이`(가장 빠른 예약 며칠 차이, 상담료 최대 차이, 경력 범위, 한 명만 하는 방식)와
  `이런 경우에는 이 전문가`(예: "채팅상담으로 받고 싶다면 → 김도현 · 채팅상담은 이 분만 가능")를 둡니다.
- **상세 = 신뢰 페이지** — 이력서 순서 대신 `이런 분께 맞아요 / 상담 후 얻는 것 → 해결해 온 문제 → 상품별 차이 →
  예약 가능 시간 → 후기 → 소개·대표 경력 → 상담 진행 방식` 순으로, 결정에 필요한 질문 순서를 따릅니다.
- **상품 = 범위가 보이는 선택지** — 상품마다 `이런 경우에 고르세요 · 상담이 끝나면 · 준비하면 좋은 것`을 같은 순서로.
- **예약 이후** — 진행 단계(예약 확정 → 상담 준비 → 상담 → 후기), 상품별 준비물이 먼저 오는 체크리스트(저장),
  시작 30분 전까지 일정 변경·취소(변경 이력 표시), 10분 전 열리는 상담방, 완료 후 후기와 같은 전문가 재상담.
- **채팅의 정직한 재정의** — 하단 탭의 '채팅'을 없애고, 예약마다 생기는 `상담방`으로 바꿨습니다.
  전문가가 보낸 것처럼 꾸민 메시지 없이, 입장 시점 · 전달 내용 수정 · 진행 기록만 실제 데이터로 보여 줍니다.

### 매칭 · 의사결정

- **카드 우선순위** — 이름·직함 → 대표 분야 · 경력 · 상담 수 → 해결하는 문제(한 줄) →
  조건 일치 이유 → 평점 → 상담료 → 가장 빠른 예약 → `상세보기`. 보조 스킬은 상세로 이동.
- **조건 일치 이유** (`src/lib/matchReasons.ts`) — 검색어 · 필터 · 정렬에서 실제로 맞은 항목만
  근거로 보여줍니다. 예: `'투자' 상담 분야`, `화상상담 가능`, `경력 16년`.
- **비교표** — 분야 → 이런 분께 맞아요 → 상담료 → 가장 빠른 예약 → 경력 → 방식 → 대상 → 상담 후 얻는 것 → 평점 → 후기 수 → 상담 건수 순.
  수치 비교가 가능한 항목에서만 `가장 김/낮음/빠름` 을 조용히 표시합니다.
- **상세 첫 화면** — 사진 · 이름 · 대표 분야 · 평점/상담 수 · 상담료 · 가장 빠른 예약 · `상담 예약하기`.
  찜/비교/공유는 보조 버튼, 경력 · 후기는 아래 섹션.
- **예약 플로우** — 한 단계에 하나의 결정. 현재 단계 · 남은 단계 수, 지금까지 고른 내용(탭하면 수정),
  다음 단계가 CTA(`다음 · 날짜`)에 표시되고, 선택 전에는 `날짜를 선택해 주세요`처럼 무엇이 필요한지 알려줍니다.
- **완료 화면** — 진행 단계 · 상담방 안내 · 상담 전 준비 체크리스트 · 일정 변경/취소 · 캘린더에 추가(.ics) · 내 예약 전체 보기.
- **마이페이지** — 다가오는 / 완료 / 취소 상담 현황과 다음 상담(D-day)을 먼저 보여주고,
  상세·준비 · 일정 변경 · 예약 취소(확인 단계 포함) · 상담방 입장(열렸을 때) · 데모 완료 처리 · 후기 작성 · 재상담 예약을 지원합니다.
- **모바일 하단** — 전문가 상세와 예약 진행 중에는 탭바 대신 예약 CTA 하나만 고정합니다.

### 화면 구조 원칙

디자인 방향은 **사람(전문가 사진)이 이끄는 하이브리드**입니다. 둘러보는 화면(홈 추천·상세 상단)은 사진을 크게,
실행 화면(예약·내 예약·예약 상세)은 상태와 다음 행동이 먼저 읽히는 기능 중심으로 둡니다.
글자 크기는 일반 앱 기준(본문 15~16px)이며, 밀도는 글자를 더 줄이기보다 중복 요소를 덜어 내는 방식으로 맞춥니다.

- **카드 한 가지 구조** — 검색 결과 카드(`ExpertCard`)는 `분야 · 이름 · 직함 · 평점·경력 → 해결하는 문제 →
  가장 빠른 예약 → 상담료 + 비교·찜` 순. 카드 전체가 상세로 가는 링크라 별도 `상세보기` 버튼을 두지 않습니다.
  홈 추천은 테두리 없는 사진 중심 `ExpertMiniCard`.
- **상세 첫 화면** — 모바일은 프로필 사진이 화면을 열고 그 위에 이름·직함을 얹으며,
  평점·상담·경력은 세 칸 지표로 나란히 보여 줍니다. 데스크톱은 사진과 이름을 나란히.
- **내 예약 = 주문 내역처럼** — `상태 · D-day · 예약번호 → 일시 → 상품 → 전문가·준비 진행 → 주요 행동 2개`,
  취소는 한 단계 낮은 텍스트 버튼으로. 예약 상세는 진행 단계를 품은 상태 카드로 시작합니다.
- **검색 화면 분야 칩** — 모바일·태블릿은 검색창 아래 가로 칩으로 분야를 한 번에 고릅니다(데스크톱은 왼쪽 필터).
- **상세 섹션 탭은 붙어 다닌다** — 스크롤해도 헤더 아래에 고정되고, 지금 읽는 섹션에 밑줄이 따라옵니다.
  상품은 태블릿 이상에서 `왼쪽: 이름·가격·예약 / 오른쪽: 이런 경우·결과물·준비물` 가로형으로 보여 상품이 늘어도 칸이 좁아지지 않습니다.
- **예약 중 고른 내용은 한 줄** — 상품·방식·날짜·시간 칩을 가로 스크롤 한 줄로 두어, 단계가 진행돼도 본문이 아래로 밀리지 않습니다.
- **내 예약 탭은 네 개** — `상담 · 찜 · 최근 본 · 프로필`, 상담 안에서 `예정 · 완료 · 취소`를 고릅니다(주소 `?tab=` 은 그대로).
  데스크톱은 예약 카드를 두 열로.
- **모바일 전체 메뉴** — 프로필 카드, 자주 찾는 곳(내 예약·찜·최근 본·상담방, 개수 표시), 한 줄 설명이 붙은 메뉴.
- **상세의 예약 패널은 하나** — 데스크톱은 히어로에서 시작해 스크롤을 따라오는 `BookingPanel`
  (상품을 바꾸면 그 길이 기준의 가장 빠른 시간이 갱신), 모바일은 하단 고정 바 하나.
- **바로 예약으로 이어지는 진입점** — 상세의 상품을 누르면 `?product=` 로 상품 단계를 건너뛰고,
  `상담 가능 시간`의 날짜를 누르면 `?date=` 로 그 날짜가 선택된 채 예약이 시작됩니다.
- **별점 분포는 전체 후기 수 기준** (`src/lib/ratings.ts`) — "후기 218"과 막대 합계가 일치합니다.
- **예약 진행 중·맞춤 찾기 질문 중에는 푸터·브릿지 CTA를 숨겨** 한 가지 선택에만 집중하게 하고, 완료·결과 화면에서 다시 노출합니다.
- **모바일 홈** — 첫 화면에 검색(한 줄 검색창) · 맞춤 찾기 · 신뢰 지표가 함께 들어오고, 바로 분야 아이콘으로 이어집니다.
  어두운 면은 첫 화면과 마지막 CTA 두 곳만 두고, 이용 흐름은 밝은 번호 타임라인으로 바꿔 섹션 리듬을 만듭니다.

- **예약 단계는 주소에 남는다** (`?step=`) — 휴대폰 뒤로가기가 예약을 벗어나지 않고 이전 단계로,
  고른 내용은 그대로 유지됩니다.
- **비교는 2명부터** — 1명만 담으면 "1명 더 담아 주세요"로 안내하고, 비교 바는 둘러보는 화면(홈·검색·상세)에만 뜹니다.
  비교는 별도 페이지(`/compare`)라 뒤로가기·새로고침에도 그대로이고, 빈 상태에서는 함께 볼 만한 전문가를 바로 담을 수 있습니다.
- **하단 고정 요소 정리** — 알림(토스트)은 모바일 상단에 하나씩, 맨 위로 버튼은 제거해
  하단에는 탭바·예약 바·비교 바만 남깁니다.
- **예약 상세** — 마이페이지에서 다시 연 예약은 축하 화면 대신 `예약 상세`로, 끝난 상담은 `상담 완료`(후기·재상담)로 보여 줍니다.

### 탐색 편의

- **검색 자동완성** — 입력 즉시 추천 검색어 · 상담 분야 · 전문가를 제안하고,
  ↑/↓/Enter/Esc 키보드 탐색을 지원합니다 (`src/lib/suggest.ts`).
- **적용된 필터 칩** — 결과 상단에 적용 중인 필터를 칩으로 노출하고 개별 해제할 수 있습니다.
- **최근 본 전문가** — 상세 진입 이력을 최대 8명까지 저장해 검색·상세 하단에 노출합니다.
- **맨 위로 버튼** — 하단 고정 바(비교 바 · 예약 CTA)와 겹치지 않도록 위치를 자동 조정합니다.
- **접근성** — 본문 건너뛰기 링크, 검색 결과 수 `aria-live` 안내,
  콤보박스 ARIA 속성, 최소 44px 터치 영역.

- **Gold** (`gold-400 #D6AC4E`) — 배지, 섹션 라벨, 히어로 액센트 등 신뢰감에 온기를 더하는 포인트
- **Cream** (`cream-50 #FDFBF8`) — 흰색/회색만 반복되지 않도록 섹션 배경에 사용

홈은 `네이비 히어로 → 크림 → 화이트 → 네이비 → 크림 → 네이비 CTA` 로
명암이 교차하도록 구성했고, 카테고리 아이콘은 분야별 색상을 부여했습니다.

### 타이포그래피

- 글자 크기는 `tailwind.config.ts` 의 단일 단계만 사용합니다 — 임의 값(`text-[20.5px]`)은 쓰지 않습니다.
  일반 앱 기준으로 맞춘 역할별 크기:

  | 단계 | 크기 | 역할 |
  | --- | --- | --- |
  | `xs` · `sm` | 12 · 13px | 캡션 · 탭바 라벨 · 칩 |
  | `base` · `md` | 14 · 15px | 메타 정보 · 보조 본문 · 버튼 |
  | `lg` · `xl` | 16 · 17px | 본문 · 강조 본문 |
  | `2xl` · `3xl` · `4xl` | 18 · 20 · 22px | 카드 제목 · 이름 · 가격 |
  | `5xl` · `6xl` · `7xl` | 24 · 26 · 30px | 모바일 페이지 제목 · 단계 제목 · 데스크톱 섹션 제목 |
  | `9xl` · `display` | 40 · 52px | 데스크톱 히어로 |

  숫자 배지(`2xs` 11px)와 로고 보조 표기(`3xs` 10.5px)만 그보다 작습니다.
- 앱 기본 높이: 헤더 56px(데스크톱 64px), 하단 탭 56px, 주요 버튼 48~52px, 최소 터치 영역 44px.
- 굵기는 제목·이름·가격에 `bold`, 히어로·로고·전문가 이름(상세)만 `extrabold`.
- 미래에이아이랩 브랜드 색은 `mirae-*` 토큰으로만 사용합니다 (제작사 표기·브릿지 CTA·소개 페이지).
